CiteProof documentation

CiteProof turns a research question into a structured literature review. These docs explain what the product does, how the research workflow runs, and how to connect the Claude Science audit layer.

What CiteProof does

CiteProof searches academic sources, screens the records it finds, extracts evidence into a table, checks DOIs and citations, and writes a structured paper. Research Mode keeps a human in the loop: you approve the scope, the literature and framework, and the hypotheses before the paper is assembled.

There are two ways to use CiteProof:

In the app

Research assistant

Run DeepSearch for a fast cited report, or Research Mode for a full paper with PRISMA 2020 tracking, an evidence table and three review gates.

Next to your agent

Claude Science + CiteProof MCP

Keep Claude Science as the researcher and use CiteProof MCP as the audit layer: protocol, PRISMA counts, screening decisions, evidence quotes and one export.

Choose your workflow

If you want CiteProof to search and draft, open the research app (hosted, or self-hosted). Start with a question, choose DeepSearch or Research Mode, and approve each review gate when it appears.

If you already work in Claude Science and want the review decisions recorded and checked, use the MCP server. The agent still searches, reads and writes; the server stores its decisions, validates their shape, checks the quotes it is given and computes the review counts.

  • Set up CiteProof for Claude Science: the Claude Desktop extension, a local npx install and the Claude Science local command.
  • Read the MCP reference: all 24 tools, their arguments, limits, results and troubleshooting.

Your first run

  1. Open the app. Use the hosted app at citeproof.top, or run your own copy with your own model and search keys.
  2. Write one review question. Keep it answerable from published literature and narrow enough to screen.
  3. Choose a mode. DeepSearch returns a fast cited report. Research Mode runs the longer pipeline and pauses at three human checkpoints.
  4. Approve the review gates. Check the scope and keywords, then the literature and framework, then the hypotheses. Nothing downstream is committed without your approval.
  5. Check the output. Read the cited claims against their sources, review the evidence table, and export the report only after the counts add up.
Expectation

Model output can be wrong. CiteProof checks structure, quotes and citation matches where it can; it does not prove that a claim is scientifically true.

Keeping these docs accurate

The MCP pages are written from the server's own specification and tool code. If the implementation and a docs page disagree, the implementation is authoritative: MCP/docs/SPEC.md and MCP/docs/CLAUDE_SCIENCE.md.

The research app is described from its source code and .env.example. If a docs page and the code disagree, the code is authoritative; please open an issue.
